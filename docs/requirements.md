## 界面重构设计（2026-11-06 讨论确定，已实现）

### 1. 左侧按流程排列的步骤

左侧工具栏改为带编号的流程步骤，按顺序操作：

| 步骤 | 进入条件 | 完成标志 |
| --- | --- | --- |
| ① 素材 | 无 | 已选中一个素材 |
| ② 字幕 | 有素材 | 当前字幕轨至少有一条字幕（必须完成，不可跳过） |
| ③ 选片 | 有字幕 | 有 AI 候选 |
| ④ 草稿 | 有候选 | 至少一个草稿 |
| ⑤ 封面 | 有草稿 | 当前草稿已保存封面配置即打勾，无需生成 JPEG；可跳过，不阻挡下一步 |
| ⑥ 导出 | 有字幕 | — |

- 每个步骤显示状态：已完成（对勾）、当前（高亮）、可进入、未满足条件（置灰，悬停说明缺什么）。
- 随时可以回到前面的步骤；往前只能进入条件已满足的步骤。
- 每页右下角固定主按钮"下一步：××"。
- "迁入项目"和"设置"放在工具栏底部，与流程步骤分开。
- 顶栏的"导出记录"按钮去掉，导出记录并入 ⑥ 导出。

### 2. 各步骤三栏分工

① 到 ⑤ 统一为：左栏放对象列表，中栏预览，右栏放选中对象的属性和操作。右栏顶部固定任务卡（进度、剩余时间、取消、错误），滚动时始终可见。

| 步骤 | 左栏 | 中栏 | 右栏 |
| --- | --- | --- | --- |
| ① 素材 | 素材列表、导入 | 原片 | 素材信息（时长、字幕数、来源链接）、删除 |
| ② 字幕 | 字幕轨卡片（语言、来源标记：人工 / 自动 / 识别 / 文件、条数）、"＋ 添加字幕"（平台获取 / 本地识别 / 导入文件）、字幕搜索与列表、说话人筛选与改名 | 原片，叠加当前字幕的实时预览；选中字幕时预览下方出现编辑条（文本、"起点设为当前""终点设为当前"） | 来源设置（平台链接与自动字幕、识别模型与说话人数、导入文件）、素材默认字幕风格 |
| ③ 选片 | AI 候选列表 | 原片定位到候选片段 | 选片设置（云端、指令）、开始选片 |
| ④ 草稿 | 草稿列表及所选草稿的片段 | 草稿渲染预览 | 片段边界与顺序、画面比例、版式、字幕风格（默认沿用素材风格，可单独更换）、开场标题 |
| ⑤ 封面 | 草稿列表 | 封面实时预览 | 封面风格、文字、取帧 |

导出功能从 ② 字幕和 ④ 草稿中移出，统一放到 ⑥。

### 3. ⑥ 导出：左配置、中预览、右导出

- 左栏：最上面选择"导出什么"（原片字幕文件、原片字幕视频、各草稿成片、各封面），下面是对应配置：
  - 字幕文件：SRT、VTT、TXT、MD。
  - 原片字幕视频：字幕内容（当前轨 / 中英双语），明确列出将使用的字幕轨，缺少的轨直接提示去 ② 获取；方式（软字幕 / 烧录）；烧录时的字幕风格；容器与分辨率。
  - 草稿成片：是否需要重新渲染，沿用草稿的画面设置。
- 中栏：按左侧配置实时预览。
- 右栏：导出按钮、输出位置与文件名、任务卡、导出记录。原片视频和草稿成片统一提供应用内预览和打开文件位置，点击文件名仍可用系统播放器打开；字幕记录不显示视频预览按钮。
- 原片视频的默认文件名沿用当前 AI 草稿的已保存标题，没有草稿时沿用素材名；导出内容仍是完整原片。字幕文件不使用草稿标题。

### 4. 字幕风格与封面风格

- 字幕风格与封面风格采用同一套机制：内置风格只读，自定义风格从某个风格复制后修改参数。
- 只开放结构化参数，不开放任意 CSS 或 ASS 样式代码，保证网页实时预览与 FFmpeg 导出使用同一份数据。
- 内置字幕风格：经典（下载器原烧录样式）、大字、底框、综艺、简洁。现有草稿字幕样式（粗体、底框）由这套风格取代，旧草稿自动对应到最接近的风格。
- 字幕风格参数：字重（常规 / 粗体）、字号（画面短边百分比）、文字颜色、描边颜色与粗细、阴影距离、底框开关与颜色、不透明度、离底距离、左右边距、每屏最多行数、第二语言字号比例与颜色、双语上下顺序。
- 封面风格参数：基于哪种内置版式（知识、访谈、游戏、Vlog、通用，版式本身不开放自定义布局）、强调色、底色、文字颜色、标题字重、字号比例、斜体、描边、遮罩强度、饱和度、对比度、标签样式、强调条开关。
- 字体只使用内置的 Noto Sans CJK SC 常规与粗体，不导入外部字体。
- 风格库由主进程保存并校验，所有项目共用。每个风格带 ID、名称、基础风格、版本和更新时间，便于以后同步到远程数据库。本轮不做导入导出。
- 管理入口：风格卡片菜单（编辑 / 复制 / 删除；内置风格只能复制）、"＋ 新建风格"；编辑器用侧边抽屉，左边是参数，右边是实时预览，可切换样例文字（中文、英文、中英双语、长句）；设置页增加"风格库"区段。
- 素材和草稿只记录风格 ID；每次渲染或导出时把完整参数存进本次记录，修改或删除风格不影响已有记录。删除正在使用的自定义风格前提示使用数量，确认后相关草稿退回其基础内置风格。
- 实时预览使用网页叠加；预览区提供"生成真实帧"，用实际烧录方式截取一帧核对效果。

### 5. 实现说明

- 流程步骤：`src/App.tsx` 按上表计算可进入与完成状态；切换到前置条件不足的素材时自动退回最后一个可进入的步骤。“下一步”固定在属性栏底部。
- 风格库：`shared/styles.ts` 定义参数与内置风格，`electron/services/styles.ts` 保存在用户数据目录 `styles.json`，删除记录保留“已删除 ID → 基础风格”的映射；删除时同步把草稿和素材默认风格改回基础风格（草稿版本号加一）。
- 字幕风格在三处使用同一份参数：网页叠加预览（`Styles.tsx`）、原片烧录与真实帧（`engine/media_processing.py` → `subtitles.write_ass`）、草稿成片（`engine/clipping.py` 改用同一个 ASS 写入器）。渲染与封面任务记录本次解析出的完整参数。
- 封面风格：内置风格不产生额外 CSS，与原外观一致；自定义参数只在与版式默认值不同处追加规则。
- 导出页：`src/components/editor/ExportWorkspace.tsx`；字幕页和草稿页不再有导出按钮，顶栏“导出记录”移除。
- 旧草稿的字幕样式 `clean` / `bold` / `box` 自动对应“简洁 / 经典 / 底框”。

## 命令行与 Agent（`clipper`，2026-11-06）

- 做法与下载器的 `galaxy` 命令一致：`clipper` 自己不处理媒体，通过本机控制通道（Windows 命名管道 / Unix 套接字，仅当前用户可连，不开网络端口）驱动正在运行的客户端；客户端未运行时，安装版启动器用 `--background` 在后台启动它。CLI 与窗口共用同一份素材、字幕、模型、风格库和任务队列。
- 每条命令支持 `--json`：标准输出只有一个 JSON 对象，进度写到标准错误；`--wait` 等任务结束。退出码：0 成功，1 失败，2 缺少前置条件（无字幕、未配置云端模型、无来源链接、模型未安装、缺少中英字幕轨），4 无法连接客户端。
- 命令按流程排列：`status`；`media import|list|show|remove`；`subtitles fetch|recognize|import|tracks|use|show|style`；`analyze`、`candidates`；`drafts create|list|set`；`export captions|video|clip|cover`；`styles list|show`。风格的新建与修改只在界面中进行。
- 安全边界：控制通道只接受白名单命令；`cli:*` 命令（导入文件、导出到指定路径）只能从控制通道发出，窗口 IPC 不认这些命令。主进程检查每个输出路径：必须是绝对路径、父目录存在、文件不存在、扩展名与导出类型一致；不会覆盖原片或已有文件。成片的最终导出在窗口里仍走系统保存对话框。
- 设置 → 常规新增“命令行与 Agent”开关（默认开启）。安装版启动时自动注册命令（Windows 写入当前用户 PATH，其他系统写 `~/.local/bin` 与带标记的 shell 配置）；开发实例只开控制通道、不改 PATH，用 `pnpm clipper <命令>` 运行。`CLIPPER_SOCKET` 可指定通道地址，供隔离测试使用。
- 实现：`shared/control.ts`、`electron/services/control.ts`、`electron/services/command-line.ts`、`electron/cli/clipper.ts`，打包配置 `vite.cli.config.ts`，产物 `dist-electron/cli/clipper.mjs`。
